# Sample logs

Small `.imul` files for testing `tools/replay.py` and the pipeline without a phone.

## synthetic_square.imul

Generated by the pipeline test `SampleLogTest` (`pipeline/src/test/kotlin/.../pdr/SampleLogTest.kt`)
from the `SyntheticWalk` generator. Regenerate it with:

```
cd pipeline && IMU_MAPPER_SAMPLES_DIR=../tools/samples ../gradlew test --tests '*SampleLogTest*'
```

Scenario (all sensors at 100 Hz for accel/gyro, rotation vectors at 100 Hz, magnetometer 50 Hz,
barometer 25 Hz, plus hardware step events):

| Time | Event |
|---|---|
| 0–2 s | standing still at the origin |
| then | walk 5 m north, `WAYPOINT "corner 1"` |
| then | walk 5 m east, `WAYPOINT "corner 2"` |
| then | walk 5 m south, `WAYPOINT "corner 3"` |
| then | walk 5 m west back to the origin, `LOOP_CLOSED "back at start"` |
| last 2 s | standing still |

Walking speed 1.2 m/s, cadence 1.8 Hz, so the true stride is 0.6667 m and the loop has about 30
steps. The phone is held with a 0.4 rad tilt and its top pointing along the walking direction
(heading offset 0). Gravity is 9.81 m/s^2 on the ENU up axis; the vertical bounce is 2.5 m/s^2,
the forward gait oscillation 1.2 m/s^2 and the lateral 0.5 m/s^2 at half the cadence. The game
rotation vector drifts in yaw by 0.003 rad/s; the fused rotation vector is drift-free and the
magnetometer sees an undisturbed field of (0, 22, -40) microtesla in ENU.

The `LogMeta` in the file carries the config the processor should use: `strideLengthM` is set 4 %
too long on purpose so the raw path ends about 1 m from the origin, which is what the loop closure
then corrects. Expected results with that config (`PipelineConfig` defaults otherwise):

- about 30 steps, distance about 20.8 m before closure
- `closureErrorM` between 0.1 and 3 m, last point within 0.3 m of the origin after closure
- z stays within a few centimetres of 0 (flat walk)

The world frame is ENU, the timestamps start at 1 000 000 000 000 ns, see `docs/CONVENTIONS.md`.
